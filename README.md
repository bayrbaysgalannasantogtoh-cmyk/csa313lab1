Хийсэн ажлууд
Энэ лабаар WSL2 (Ubuntu) орчиндоо Node.js болон Playwright суулгаж, `https://www.saucedemo.com` дадлагын сайт дээр UI автомат тест бичлээ. Эхлээд `npm init playwright@latest .` болон `sudo npx playwright install-deps` хийж Chromium, Firefox, WebKit хөтөчүүдээ бэлдсэн.

`tests/mytest.spec.ts` файлд хоорондоо хамааралгүй нийт 3 тест бичсэн (`beforeEach` дээр хуудсаа шинээр нээдэг, нэвтэрсэн тестүүд төгсгөлдөө `Logout` хийж гардаг):
- Амжилттай нэвтрэх: `standard_user` / `secret_sauce`-ээр ороод URL нь `/inventory.html` болсон болон `Products` гарчиг харагдаж байгааг шалгаад гарна.
- Амжилтгүй нэвтрэх: буруу нууц үг оруулахад `Epic sadface: Username and password do not match any user in this service` алдааны мессеж гарч, нэвтрэх хуудсан дээрээ үлдэж байгааг шалгана.
- Нэвтэрсний дараах үйлдэл: эхний барааг (`Sauce Labs Backpack`) сагсанд нэмээд `Remove` товч болон сагсны тоо `1` болсныг шалгаж, сагсны хуудас (`/cart.html`) руу орж барааны нэр орсон байгааг баталгаажуулаад гарна.

Тестүүдээ бичихдээ XPath ашиглалгүй `getByPlaceholder`, `getByRole`, `getByText` зэрэг Playwright-ийн locator-уудыг хэрэглэсэн. XPath нь хуудасны HTML бүтэц, `div`-ийн дараалал бага зэрэг өөрчлөгдөхөд л шууд эвдэрдэг, бас дараа нь уншихад ойлгомжгүй байдаг. Харин хэрэглэгчийн нүдэнд харагдах текст, товчны нэрээр хайхаар код нь цэвэрхэн болохоос гадна загвар өөрчлөгдсөн ч тест тэр бүр унахгүй. Анх `Logout` дээр `getByRole('link')` бичээд timeout болсон ч `getByText('Logout')` болгож зассанаар 3 хөтөч дээр нийт 9 тест (`9 passed`) бүгд амжилттай ажилласан.

Мөн `npx playwright codegen` ажиллуулж гарсан кодыг өөрийн бичсэнтэй тулгаж үзээд, `npx playwright test --trace on` ажиллуулж `trace.zip` болон HTML тайланг (`playwright-report/`) үүсгэж реподоо хавсаргалаа.

Playwright ба Selenium харьцуулсан ажиглалт

Playwright ашиглаж үзэхэд Selenium-тэй харьцуулахад орчин бэлдэх нь хамаагүй амархан санагдлаа. Selenium дээр хөтөч бүрд тусдаа driver татаж тохируулах хэрэгтэй байдаг бол энд нэг командаар бүх хөтөч нь суучихдаг юм байна. Бас элемент ачаалагдахыг гараар хүлээлт (wait) бичилгүйгээр Playwright өөрөө автоматаар хүлээдэг нь тест бичихэд их амар байсан. Код бичих явцад `codegen` ажиллуулаад хуудас дээр дарахад л бэлэн locator-той код гаргаад өгчихдөг нь цаг хэмнэж байлаа. Хамгийн таалагдсан зүйл нь Trace Viewer байв — тест унахад зөвхөн текстийн лог харах биш, яг аль алхам дээр юу харагдаж байсныг зураг шиг гүйлгээд харчихдаг болохоор алдаагаа хурдан олсон. Түүнчлэн тест бүр цэвэр орчинд тусдаа ажилладаг тул өмнөх тестийн төлөв дараагийнхдаа нөлөөлөхгүй байгаа нь анзаарагдсан. Selenium бол хуучин төслүүдэд одоо ч их хэрэглэгддэг байх, гэхдээ шинээр UI тест бичихэд Playwright илүү хурдан бөгөөд ашиглахад эвтэйхэн байна.
